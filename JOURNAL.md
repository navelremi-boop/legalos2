## 2026-10-12 — J11 étape 1b : décision de conception des brouillons (cahier § 3.8 : « localement puis dans le dossier Brouillons de la boîte »)

Constat (Explore, lecture seule) : le poste n'a aucun éditeur de rédaction ; la file d'envoi n'est pas synchronisée (GET `/messagerie/file-envoi`) ; le connecteur d'upload du poste n'accepte pas `messages` ni la file ; le moteur ne relève que INBOX et Sent/Envoyés ; `SessionActions::appender` ne pose aucun drapeau ; aucune route de complétion ni de téléversement de pièces.

**Décision** (liberté d'action § 4.1, invariant 5 : pas de synchronisation maison) : le brouillon est une **table synchronisée par PowerSync, propre à son auteur** (`brouillons_message`, flux filtré par `auth.user_id()`), écrite depuis le poste par la file d'upload existante (donc disponible hors ligne, repris sur un autre poste du même utilisateur) vers l'API, qui **recopie** chaque version dans le dossier Brouillons du serveur IMAP (APPEND avec `\Draft`, l'ancienne version du même Message-ID retirée) ; l'envoi (`POST /messagerie/brouillons/{id}/envoyer`) crée la ligne de `file_envoi` puis retire le brouillon et sa copie IMAP. Pièces d'un brouillon : téléversement en ligne (BYTEA, 25 Mio cumulés), seules leurs métadonnées sont synchronisées. **Alternative écartée** : relever le dossier Brouillons IMAP par le moteur et en faire la source de vérité : l'édition hors ligne exigerait une file d'écriture maison, et la contrainte unique `(compte_id, uid_validity, uid)` de `messages` ignore le dossier. **Limite connue, assumée** : un brouillon commencé sur le téléphone n'apparaît pas dans l'app (Brouillons n'est pas relevé) ; l'inverse fonctionne. Complétion des destinataires : route API sur l'annuaire du cabinet et sur les adresses des mails que l'utilisateur a le droit de lire (jamais un dossier restreint ou une boîte nominative d'autrui).
